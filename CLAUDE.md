# FinBridge — контекст за Claude Code

SaaS за български счетоводни кантори и малки фирми: „Payhawk плюс счетоводство за малки фирми". Собственикът говори български; отговаряй на български, кратко, с резултата най-отпред.

## Какво е това

- `server.js` — целият сървър. Node.js 22, **без външни пакети** (`node:http`, `node:sqlite`). Това е съзнателно решение; не добавяй зависимости без нужда.
- `public/index.html` — интерфейс на счетоводителя. Логиката `Core` е между `/*CORE-START*/` и `/*CORE-END*/` и се зарежда и от сървъра с `new Function`.
- `public/company.html` — финанси на фирмата (разходи, фактури, бюджети). Логиката `Fin` е между `/*FIN-START*/` и `/*FIN-END*/`, също споделена със сървъра.
- `public/login.html`, `public/portal.html` (клиентски портал през таен линк `/u/<token>`), `public/security.html` (двуфакторен вход и журнал).
- `qr.js` — QR генератор без пакети (за двуфакторния вход).
- `admin.js` — команди от терминала. `scripts/snapshot.js`, `scripts/restore.js` — резервни копия.
- `HANDOFF.md` — пълното предаване: история, решения, състояние, следващи стъпки. **Прочети го първо.**
- `AUDIT.md` — техническият одит: какво е намерено, поправено и какво остава.
- `REVIEW.md` — независимата проверка: находки, какво е поправено, предложения за доизграждане, подобрения и надграждане.
- `README.md` — функции, настройки, ограничения.

## Модел на данните

Много наематели по `office_id`. Потребители на фирма имат `firm_id` и `crole` (owner, approver, member). `offices.solo=1` е самостоятелно регистрирана фирма. Финансовите записи са в `fin(type, status, data JSON)`: expense, bill, invoice, budget, credit, recur.

## Команди

```
npm test            # единични и API тестове, вкл. одитните опити за атака
npm run test:e2e    # Playwright в Chrome (PLAYWRIGHT и CHROME сочат пътищата)
node server.js      # PORT, DATA_DIR; виж README за останалите настройки
```

Тестовете са обикновени `node:assert` скриптове в `test/`. Помощници: `test/helpers.js` (`startServer`, `mockAI`, `fakeSMTP`).

## Правила

- **Не качвай на безплатния Render план.** Там няма диск и всяко качване трие акаунтите. `render.paid.yaml.example` е предложението за платен план.
- Не сливай в `main` и не качвай без изрично „слей" от собственика.
- Всяка промяна идва с тест. Преди да заявиш, че нещо работи, пусни `npm test` и `npm run test:e2e`.
- Сигурност: всяка заявка, различна от GET, носи заглавие `x-fb: 1`; всяка заявка към данни филтрира по `office_id`; текст от потребител минава през `esc()` преди да влезе в HTML; страниците са с CSP nonce, без вградени обработчици (`onclick=`).
- Никога не въвеждай пароли и ключове; собственикът ги задава сам в средата.
